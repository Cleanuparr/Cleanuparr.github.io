Seeker

The Seeker automates searching for missing items and quality upgrades across your Radarr, Sonarr, Lidarr, Chaptarr, Sportarr and Whisparr (v2 and v3) libraries. It runs on a configurable schedule and works through your library one item at a time to avoid overwhelming your indexers.

Search Enabled

Master toggle for all searching. When disabled, neither replacement searches nor proactive searches will run.

Search Interval

How often the Seeker job runs, in minutes. Available options are 2, 3, 4, 5, 6, 10, 12, 15, 20, and 30 minutes.

Warning

Using a very low interval will trigger searches more frequently, which significantly increases the load on your indexers. This can result in rate limit warnings or a ban from your indexer.

Replacement Search

Replacement search is always enabled when Search is on and cannot be disabled. Whenever a download is removed from an *arr queue (by Queue Cleaner or any other mechanism), Seeker immediately queues a replacement search for that item. Replacement searches always take priority over proactive searches, which means the proactive cycle is paused until all queued replacement searches have been processed.

Proactive Search

Proactive search works through your library systematically to find items that are missing or could be upgraded. Each run processes one item at a time to keep indexer load predictable.

Note

Proactive search operates in cycles. Seeker tracks which items have been searched in the current cycle. Once every eligible item in an instance has been searched, the cycle completes and the next one starts after the minimum cycle time.

For Radarr, each movie is one item. For Whisparr v3, each movie or scene is one item. For Lidarr, each album is one item. Seeker draws an artist first, then one of its albums. For Chaptarr, each audiobook or ebook is one item. Seeker draws an author first, then one of its books, earliest release date first. For Sportarr, each event is one item, whatever its league or season. For Sonarr, a cycle holds season units and episode units. Search Mode picks the unit for regular and daily seasons. Specials and airing anime seasons go one episode at a time. Whisparr v2 treats sites as series and scenes as episodes, so its cycle holds year units like Site 2024 and scene units like Site 2024-05-12. Cycle progress counts the searches still needed.

The Searches tab shows per instance how many items the current cycle searched, how many are left, how long it has been running and how long the previous cycle took. Items in the download queue are not counted as left. Dry run tracks its own cycles and never moves the live one.

To get notified when a cycle completes, turn on Seeker Cycle Completed on a notification provider.

Reset cycle on an instance card closes the current cycle and starts a new one right away, so every eligible item can be searched again. It skips the minimum cycle time once. The button stays disabled until the cycle has searched something. With dry run on, it resets the dry run cycle.

The Eligibility row on an instance card counts what passed each filter on the latest run. It starts with the movies or series in the library, then those released and past the grace period (or available in Radarr, with Follow Radarr availability), monitored, and past the tag filters. The last stage counts the units that need a search, split into in queue, recently grabbed, searched this cycle, and left. It also shows a resting count. Items resting under Rest Items That Find Nothing don't hold up cycle completion.

Preview on an instance card reads the instance live and lists the next 10 units the selection strategy would pick, plus every excluded item with the first filter that dropped it. Preview lists resting items as "Resting". You can filter the excluded list by reason or title. Preview searches nothing and saves nothing. With a random or weighted strategy, the next up list is one random draw, so the next run can pick other items. A series with missing episodes in several seasons also gets a random season draw under any strategy, except Custom Format Gap Weighted, which searches the series' missing unit, else its largest gap unit. When the cycle is complete and waits for the minimum cycle time, the preview shows when the next cycle starts.

Each Sonarr search event records a content kind: Standard (a regular season or episode), Daily (a daily series season or episode), Anime (an anime season or episode) or Special (an episode from season 0). Radarr and replacement searches carry none. The Searches tab can filter events by content kind.

Note

Seeker reads the Missing and Cutoff Unmet lists of each *arr instance. Proactive search on Radarr needs Radarr v5.6 or newer, the first version with those lists. Whisparr v3 needs v3.1 or newer. Lidarr albums come from the same two lists. Chaptarr books do too. Sportarr events do as well, except that the Missing list comes from Sportarr's own API so Seeker can tell postponed and cancelled events apart.

Note

Seeker skips postponed and cancelled Sportarr events. Sportarr also runs its own backlog search every 6 hours for leagues that have it enabled, so turn one of the two off to avoid searching twice.

Note

For an item to be eligible, it has to be released digitally. For example, if the item is currently in cinemas, it will be skipped until it has a proper digital release.

Proactive Search

When enabled, Seeker will periodically search for missing items and quality upgrades across your library. Each run selects one item according to the configured selection strategy and triggers a search in the corresponding *arr application.

Enable Missing Search

Missing search is always enabled when proactive search is on. Items with no file are always included as search candidates, regardless of any other quality upgrade settings.

Selection Strategy

Controls how Seeker selects which item to search next from the pool of eligible candidates. Available strategies:

  • Balanced Weighted: Prioritizes items that are both newly added and have not been searched recently. A good default for most libraries.
  • Oldest Search First: Picks the items that went longest without a search, never-searched items first.
  • Oldest Search Weighted: Favors items that have not been searched recently, but still gives other items a chance.
  • Newest First: Always picks the most recently added items first. Best for keeping new additions up to date quickly.
  • Newest Weighted: Favors recently added items, but still gives older items a chance.
  • Random: Every eligible item has an equal chance of being picked with no prioritization.
  • Custom Format Gap Weighted: Favors items furthest below their custom format cutoff, while still rotating through items that were searched long ago. Missing items count as furthest below. It needs Use Custom Format Score on the instance; instances without it use Balanced Weighted.
Note

Regardless of the strategy, items already searched in the current cycle are excluded from selection. The strategy only determines the order in which unsearched items are considered.

Search times come from the *arr instance, so manual searches and searches from other tools count. Items with the same search time go in random order.

Monitored Only

When enabled, only items that are marked as monitored in the *arr instance will be included as search candidates. Unmonitored movies, series, and episodes are skipped entirely. For Lidarr, an album counts as monitored only when its artist is monitored too. For Chaptarr, a book counts as monitored only when its audiobook or ebook side and the same side of its author are monitored. Sportarr follows the event's own monitored flag, so the league's flag does not matter and the toggle does not appear.

Use Cutoff

When enabled, items that already have a file but have not yet met the quality profile's cutoff will be included as upgrade candidates. Items that have already met their cutoff are excluded unless Use Custom Format Score also applies to them.

Use Custom Format Score

When enabled, items whose current custom format score is below the quality profile's cutoff format score will be included as upgrade candidates. Seeker uses cached score data that is kept up to date by the Custom Format Score Syncer, which runs automatically when this setting is enabled.

Note

Custom format scores are tracked at the episode level for Sonarr and per scene for Whisparr v2. If a series has episodes with scores below the cutoff, the corresponding season will be searched. After an update to Cleanuparr, these episodes count again once the syncer has run.

For Lidarr, an album's score is the score of its first track file, the one with the lowest id. This is how Lidarr compares an album. An album with a track missing a file has no score entry.

This setting does not apply to Chaptarr: its books carry no custom format score. Chaptarr still scores the releases a search finds. The same goes for Sportarr.

Round Robin

When enabled, only one instance is processed per Seeker run. Instances are rotated based on which was processed least recently, spreading indexer load evenly across all configured instances.

When disabled, all enabled instances are processed on every run.

Warning

Disabling round robin will trigger a search for each enabled instance on every run. With a low search interval and multiple instances, this can result in a large number of indexer requests in a short period.

Post-Release Grace Period

The number of hours to wait after content is released before including it as a search candidate. This gives indexers time to process new releases before Seeker attempts to find them.

Set to 0 to disable the grace period and search immediately.

Radarr instances set to Follow Radarr availability ignore the grace period.

Whisparr v3 counts the grace period from each movie or scene's release date.

Whisparr v2 counts the grace period from midnight UTC on each scene's release date. A scene without a release date counts as not released.

Lidarr counts the grace period from each album's release date. An album without a release date counts as released. A Chaptarr book without a release date counts as released too.

Quiet Hours

Set a daily window in which Seeker does not start proactive searches. Replacement searches keep running inside the window.

Times use the container's local time. Set the TZ environment variable to your timezone. The default is Etc/UTC.

Start is inclusive and end is exclusive. Start and end must differ.

A window that ends before it starts runs past midnight. For example, 23:00 to 07:00 blocks proactive searches from 23:00 until 07:00 the next morning.

Seeker resumes proactive search at its first scheduled run after the window ends.

Instance Configuration

Per-instance settings allow you to control which Radarr, Sonarr, Lidarr, Chaptarr, Sportarr and Whisparr (v2 and v3) instances participate in proactive search and how they behave.

Important

An instance must also be enabled in Arr Settings for it to be used by Seeker.

Enabled

Enables this instance for proactive search. When disabled, the instance will not be included in any proactive search cycles. Replacement searches are not affected by this setting — they are always processed for any instance where a download was removed.

Include Tags

Arr tags that limit proactive search. When this list has tags, only a movie or series carrying at least one of them gets searched. Leave it empty to search every item.

Skip Tags take precedence: an item carrying both an include tag and a skip tag is skipped.

Examples:

anime
4k

Skip Tags

Arr tags to exclude from search. Any movie or series in the corresponding *arr application that has one of these tags assigned will be skipped entirely during proactive search, even when it also carries an include tag.

For Chaptarr, a book uses the tags of its side: the author's audiobook tags or ebook tags.

Examples:

no-search
skip-upgrade
manual-only

Active Download Limit

When the downloads in the arr queue reach this limit, Seeker skips the proactive search for that instance. This keeps Seeker from triggering new searches while the download client is busy.

The count includes every download the client still works on, including torrents still fetching metadata and torrents queued in the client. Finished downloads waiting for import do not count.

Only items that a download client has are counted. Items that are still queued inside the *arr application, such as releases held by a delay profile, are not counted.

Set to 0 to disable this check and always run the proactive search regardless of queue activity.

Enable Ignore Struck Downloads below to leave the downloads that Queue Cleaner flagged out of this count.

Ignore Struck Downloads

When enabled, a download that Queue Cleaner struck on its most recent completed run does not count toward the Active Download Limit. A slow or stalled download stops holding a slot, so Seeker keeps searching for releases that can still complete.

Important

Use carefully! Because of the volatility of strikes, downloads that continuously receive strikes and recover may cause more downloads than expected to accumulate in the queue.

The strike types that count are:

  • Stalled
  • Slow Speed
  • Slow Time
  • Downloading Metadata
  • Errored

Only downloads that have received strikes in the most recent completed Queue Cleaner run are ignored from the active downloads limit.

Recent Grab Window

Seeker reads the arr's grab history for this many hours and skips every item grabbed in that window, even when the download already left the queue (imported, failed and removed, grabbed by RSS or another tool).

For Sonarr, a grabbed episode skips its whole season for the window when the season is searched whole.

Set to 0 to turn this off.

Default is 24, maximum is 168.

Rest Items That Find Nothing

After 3 searches in a row grab nothing, Seeker skips the item for 1 cycle. Each further miss doubles the rest: 1, 2, 4, then at most 8 cycles. A rest also ends when Max Rest (Days) passes, whichever comes first.

Only a grab from a Seeker search clears the count and the rest. Failed or timed-out searches don't count as misses.

A Chaptarr search with no result tries every query tier on every indexer, so a book that keeps missing rests. A Sportarr event search does the same with every query variant, which makes it heavier on your indexers than a Sonarr search.

Seeker counts misses even while this setting is off, so turning it on uses real history.

Resetting the cycle keeps rests. The new cycle counts as one cycle passed.

When every eligible item is resting, the cycle still rolls over after Min Cycle Time, so rests keep counting cycles.

Default is off.

Max Rest (Days)

A rest always ends after this many days since the item's last search, even if cycles are slow. The cycle count or the days end the rest, whichever comes first.

Default is 30, range is 1 to 365.

Min Cycle Time (Days)

The minimum number of days that a complete search cycle must span before a new cycle can begin. Once all eligible items in an instance have been searched, Seeker will not start a new cycle until this many days have passed since the cycle started.

Reset cycle on the Searches tab skips this wait once.

Search Mode

Sonarr and Whisparr v2. Picks how the Seeker searches a regular or daily season. For Whisparr v2, a season is a year.

  • Auto searches a whole season only when the season has finished airing and every aired monitored episode in it needs a search. Otherwise it searches one episode per run.
  • Season always searches the whole season.
  • Episode always searches one episode per run.

A season search returns mostly season packs. With default settings, Sonarr skips a pack unless it can upgrade every file in it, so a season with a few wanted episodes rarely gets a grab. Episode searches find single releases, but each partly wanted episode adds one run to the cycle.

Specials and anime follow their own rules below in every mode.

Default is Auto.

Release Gate

Radarr only. Picks when the Seeker treats a movie as released.

  • Release dates searches a movie once Radarr marks it released and its digital, physical or cinema date is past the grace period.
  • Follow Radarr availability searches a movie once Radarr counts it as available. Radarr decides from the movie's minimum availability plus its availability delay, and the grace period does not apply. Movies Radarr doesn't count as available show Not available in Radarr.

Default is Release dates.

Whisparr v3 has no Release Gate. It searches an item once Whisparr marks it released and its release date is past the grace period.

Lidarr has no Release Gate. An album counts as released by its release date, with the grace period applied.

Chaptarr has no Release Gate. A book counts as released by its release date, with the grace period applied.

Search for Specials

Sonarr only. Always on and cannot be disabled.

The Seeker searches specials (season 0) one episode at a time. Sonarr runs two indexer queries for every special, so a season search would query every special back to back.

Search for Anime

Sonarr only. Always on and cannot be disabled.

The Seeker searches an anime season whole once every episode in it has aired or airs within 24 hours. Before that, it searches the episodes one at a time. Sonarr uses the same rule, and runs one query per aired episode when a season search comes too early.
